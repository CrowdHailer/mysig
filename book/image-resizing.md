# Image Resizing

Image resizing needs an external image engine. Mysig should not implement JPEG, PNG, WebP, AVIF, EXIF, or color-profile handling in Gleam. The right boundary is a typed Gleam request interpreted by a Node runner using Sharp.

## Required Node Dependency

Install Sharp in projects that resize images:

```sh
npm install --save-dev sharp
```

Sharp provides the operations needed for Zola-style parity:

- read metadata, including width and height
- resize with `fit`, `cover`, `contain`, and `inside` semantics
- preserve or strip metadata intentionally
- rotate according to EXIF orientation
- output JPEG, PNG, WebP, and AVIF
- control quality and progressive JPEG output

## Required Gleam Model

Mysig needs to model transforms as data before calling Sharp. The public API should be shaped like this:

```gleam
pub type Format {
  Original
  Jpeg
  Png
  Webp
  Avif
}

pub type Fit {
  Fit
  Cover
  Contain
  Inside
}

pub type Resize {
  Resize(
    path: String,
    width: Option(Int),
    height: Option(Int),
    fit: Fit,
    format: Format,
    quality: Option(Int),
  )
}

pub type Metadata {
  Metadata(width: Int, height: Int, format: String)
}
```

The runner should expose two effects:

- `metadata(path)` returns width, height, and detected format.
- `resize(request)` returns a Mysig `Asset` whose URL points at a fingerprinted generated image.

## Output Naming

Generated images must be content-addressed like other Mysig assets. The source bytes and transform request both affect the output.

Recommended logical key before hashing:

```text
<source-path>?w=<width>&h=<height>&fit=<fit>&format=<format>&quality=<quality>
```

Recommended final public name:

```text
<basename>.<transform-label>.<sha256>.<ext>
```

Example:

```text
gallery/2021-04-30.jpg?w=900&h=900&fit=inside&format=webp&quality=82
2021-04-30.w900-h900-inside-q82.4f8c....webp
```

Hash the generated bytes, not just the request. That preserves the existing Mysig cache rule: if the bytes change, the URL changes.

## Cache Keys

The image cache key should include:

- source file path
- source file digest
- width
- height
- fit mode
- output format
- quality
- Sharp version
- Mysig image pipeline version

Including the source digest means changing the original image invalidates every derivative. Including tool versions lets Mysig intentionally rebuild images after Sharp behavior changes.

## Zola-Style Gallery Parity

Zola's common gallery pattern does two things:

```tera
{% set meta = get_image_metadata(path=asset) %}
{% set landscape = (meta.width / meta.height) > 1.2 %}
{{ resize_image(path=asset, width=900, height=900, op='fit') }}
```

The equivalent Mysig flow should be:

```gleam
use meta <- image.then(image.metadata(path))
use thumb <- image.then(image.resize(image.Resize(
  path: path,
  width: Some(900),
  height: Some(900),
  fit: image.Inside,
  format: image.Original,
  quality: None,
)))

let width_class = case meta.width > meta.height * 12 / 10 {
  True -> "md:w-1/3"
  False -> "md:w-1/4"
}

h.img([a.src(asset.src(thumb)), a.class(width_class)])
```

This preserves both parts of the old behavior: metadata-based layout and resized image URLs.

## Responsive Images

A higher-level helper can generate several resize requests and return `srcset` data:

```gleam
pub type Variant {
  Variant(width: Int, asset: asset.Asset)
}

pub fn srcset(variants: List(Variant)) -> String
```

Example widths:

- `480` for phones
- `900` for cards and gallery thumbnails
- `1400` for large article images
- `2200` for high-density hero images

## HTML Rules

Every resized image should render with useful attributes:

- `src` from the chosen fallback variant
- `srcset` for responsive variants
- `sizes` matching the layout
- `width` and `height` from metadata to reduce layout shift
- `alt` from content metadata, never guessed from the filename
- `loading="lazy"` except for the main above-the-fold image
- `decoding="async"` for non-critical images

## Failure Rules

Image errors should fail the build. Do not silently copy originals when a resize fails, because that hides broken deploys and creates performance regressions.

Good error messages include:

- source path
- requested transform
- Sharp error
- whether the file was missing, unsupported, or invalid

## Implementation Checklist

- Add `sharp` to `package.json` dev dependencies.
- Add a Node FFI module that calls Sharp for metadata and resize.
- Add a Gleam `mysig/image` module with typed requests and results.
- Add a server runner that turns resize requests into fingerprinted `/assets` files.
- Add a dev cache under `build/mysig/images` keyed by source digest and transform.
- Add tests for output names, cache keys, and metadata-based gallery classes.
- Add a migrated gallery example that proves Zola `resize_image(... op='fit')` parity.
